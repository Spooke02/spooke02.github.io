AI API cheat sheet

The request shapes, status codes and habits that make an AI feature reliable. Check each provider's own docs for current model names and limits.

Two request shapes cover most providers

OpenAI-compatible: POST to {base_url}/chat/completions with the header Authorization: Bearer YOUR_KEY (local servers often need none). The body needs model and messages. The reply text is in choices[0].message.content, and token counts are in usage.prompt_tokens and usage.completion_tokens. The system prompt is the first message with role "system".

Anthropic (Claude): POST to https://api.anthropic.com/v1/messages with the headers x-api-key and anthropic-version: 2023-06-01. The body needs model, max_tokens and messages; the system prompt is a top-level system field. The reply is a list of content blocks where the type is "text", and usage is input_tokens and output_tokens.

Base URLs for OpenAI-compatible services

  • Google Gemini: https://generativelanguage.googleapis.com/v1beta/openai (a free tier is available)
  • Groq: https://api.groq.com/openai/v1
  • OpenRouter: https://openrouter.ai/api/v1
  • Ollama (on your own PC, no key): http://127.0.0.1:11434/v1

Model names change often and differ per account. Test with a tiny request first ("Reply with: ok").

HTTP status codes and what to do

  • 400: bad request (shape, model name, too long). Fix it; do not retry.
  • 401 / 403: wrong key or no permission. Do not retry.
  • 404: wrong URL or unknown model.
  • 408 / 429: timeout or rate limit. Retry with backoff and honour the Retry-After header.
  • 500 / 502 / 503: provider problem. Retry with backoff, then fall back to another provider.

A retry policy that works

wait = base * 2**attempt * random(0.5..1.0)   # exponential backoff with jitter
use Retry-After if the server sends it; cap at about 60 s; 2-3 retries, then fall back

Getting dependable JSON

  • Say "reply with only a JSON value", give the exact shape, and use temperature 0.
  • Parse tolerantly: replies are sometimes wrapped in code fences or have a sentence before the JSON.
  • Validate types, required keys, allowed values and ranges. Never trust an unchecked number or category.
  • If a reply is wrong, retry once and include the exact error.
  • Decide what happens if it still fails: a rule-based fallback or a clear message, not a crash.

Cost, speed and safety

  • Cache answers for identical requests and use the smallest model that passes your tests.
  • Rate-limit on your side to protect free-tier quotas, and log tokens and latency.
  • Keep API keys in environment variables, never in source code or a public repo; redact them from logs.
  • Treat model output as untrusted: validate it, and escape it before showing it on a web page.
  • Treat text you feed in as possible prompt injection, and rate-limit any public endpoint that calls a model.
